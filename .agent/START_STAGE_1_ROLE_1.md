# Этап 1. Участник 1 — правила аукциона и сборка

Ваш результат к концу второго дня — другой человек может запустить игру и подтвердить на экране, куда делись каждые $5 ставки. Работайте из корня проекта. Каждый блок цитаты — отдельный запрос для агента. После блока передайте результат второму разработчику. Для контракта и проверки денежных переходов предлагаю GPT-6.2 Astra High, для реализации по согласованным типам — GPT-6.2 Sol High. При доступе к 6.1 используйте GPT-6.1 Sol High с тем же контрольным примером.

## 1. Утро первого дня. Общая основа

> Прочитай .agent/PLANS.md и .agent/EXECPLAN.md. Выполни подготовительную часть этапа 1. Проверь содержимое рабочей копии, версии Node и npm. Ты владеешь package.json, lock-файлом, конфигурацией, index.html, src/main.ts и src/game/. Создай минимальный проект TypeScript/Vite/Vitest с командами из плана. В src/game/contract.ts опиши GameState, GameView, Command, тип функции отправки действия. Для GameView зафиксируй фазу, номер ревизии, банк, текущую цену, следующую сумму ставки, видимые предметы с id, подсказки, разрешённые действия и поля квитанции. Данные раскрытых находок доступны только после покупки. Уточни поля и допустимые команды для каждой из четырёх фаз на примере $100 → $70 → $115. Зафиксируй сигнатуру mount из плана. Подготовь типизированные примеры GameView для осмотра, ответа соперника $25 и итоговой квитанции в src/game/exampleViews.ts. Проверь компиляцию и сборку каркаса. Передай У2 контракт, примеры, команду запуска и список файлов одной согласованной версии. Сообщи, какие проверки ещё невозможны. Обнови Progress по факту.

У2 может начать зарисовку раньше, а код экрана — как только получит эту передачу. Согласуйте изменение типов до изменения обеих сторон.

## 2. Первый день. Ставка, выигрыш и выход

> Реализуй правила учебного лота из .agent/EXECPLAN.md в src/game/engine.ts. Экспортируй newGame, applyCommand и getView. Осмотр открывает подсказку, первая ставка $20 получает ответ $25, далее игрок может выйти либо дать $30. При победе спиши цену один раз, раскрой велосипед $35 и инструмент $10. sellAll начисляет $45, показывает выручку и чистую прибыль, nextLot переносит фактический банк в следующий лот. При выходе покажи результат без списания и разреши следующий лот. Блокируй действие в неподходящей фазе, ставку сверх банка и событие со старой ревизией. Напиши проверки через публичные функции: победа, пас, повторная продажа, двойная ставка одной ревизии, нехватка доллара и отсутствие скрытых цен в представлении до покупки. Выполни npm test и npm run build. Передай У2 фактическое поведение команд и замечания к примерам. Отметь в ExecPlan только проверенное.

## 3. Второй день. Подключение и приёмка

> Получи реализацию mount от У2. В src/main.ts свяжи реальный GameState, applyCommand, getView и перерисовку после принятой команды. Убедись, что действие относится к ревизии показанного экрана. Проверь первый запуск из чистой страницы и переход на второй лот без перезагрузки. Выполни npm test, npm run build, запусти приложение и пройди обе ветки обычными кнопками. Сверь банк после победы до продажи, выручку после продажи и деньги после паса. Если экран не согласуется с правилами, передай У2 точные входные данные и действие; дефект движка исправь сам. После независимого прогона У2 внеси результаты, открытые проблемы, команды и дату в Progress и Outcomes & Retrospective. Для передачи этапа укажи версию либо список изменённых файлов, подтверждённые числа и первый шаг этапа 2.

Этап принят, когда У2 воспроизвёл расчёты на общей сборке, а игрок смог объяснить своё решение до раскрытия коробки. Если осмотр не помог, вместе поправьте подсказку и повторите показ.
